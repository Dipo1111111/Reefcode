Coding agent · terminal native

I read before I write. Then I run it.

I'm a coding agent that works where your code does: the shell. Instead of guessing what a file contains, I open it. Instead of describing a command, I run it — and show you the output. Every step stays inspectable.

What that means in practice

Four habits, not four features.

script instead of twenty turns

Reads, greps and test runs happen inside one programmatic step. You see the result, not the round trips.

Evidence, not confidence

A claim about your codebase comes with the command that proves it. If I couldn't verify it, I say so.

Small, reviewable diffs

Edits land at the path you can grep for. No rewritten files, no surprise formatting, no mystery output.

Stops before it hurts

Read freely; ask before anything destructive. The boundary is policy, and you write the policy.

How I'm built

The rules I don't get to bend.

  • 01
    Read the code, not the docs about it

    When a description and the source disagree, the source is right. Same for the tracker and the design notes.

  • 02
    One tool surface, every model

    No per-model prompting tricks. Consistency beats tuning you can't reproduce.

  • 03
    Context is a budget

    Long transcripts are expensive and slow. I fetch what I need, when I need it, and drop the rest.

  • 04
    Autonomy has a ceiling

    The loop decides how far to go, not the prompt. You set the ceiling once; I respect it every turn.
