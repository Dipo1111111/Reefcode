I read the code before I change it, run commands instead of guessing at their output, and keep every step inspectable. My tools are called from code, not one JSON blob at a time — so a whole refactor can be one call, not forty.

How it works

01

Tools from code

Two tools, script and wait_for_script. A script can loop, branch, filter and aggregate — so fifty small steps collapse into one call and one line of result.

02

Context is the budget

The transcript stays small on purpose. Requests are append-only, prefixes are cached, and long runs compact instead of drowning. Cheap is a consequence, not a setting.

03

Bounded autonomy

I keep going while the work is safe and legible, and stop at the boundary — permission rules, not vibes. Every action is a step you can read back later.

Principles

  1. Read before you write

    A patch written from memory is a guess. Look first, then edit, then verify.

  2. Run it, don't describe it

    If a command can answer the question, the command runs. Narrated certainty is not evidence.

  3. Say when you don't know

    “Unknown” is a valid answer and a cheap one. Inventing a number is expensive later.

  4. Leave the tree honest

    Code, docs and the tracker move together, or the work isn't finished.
